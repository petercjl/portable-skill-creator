# Adjust flows and strategies independently

Trigger: adding, removing, merging or reordering business nodes, or changing judgment methods. Return to main-line step 4 with revised contracts and impact scope.

Give each business node a stable identity. Insertion defines inputs from existing producers and outputs for consumers; removal reconnects consumers to valid replacement producers; merging identifies which outputs and acceptance standards survive. Validate required inputs, output types and complete paths to final deliverables. Preserve previous workflow revisions and removed-node evidence. Detect cycles and dangling references before activation; modeling an iterative business loop requires explicit iteration attempts rather than a cyclic dependency graph in the supplied template.

Core domain strategies live in routed references. SKILL.md retains order, handoffs, hard constraints, resource entry points and acceptance contracts. Replacing a strategy preserves the node's output interface or explicitly migrates consumers. Add a theory with its applicability, retrieval route, decision method, evidence needs and expected output contribution. A file's presence alone does not activate it.

Knowledge updates affect only runs that actually use the new content. A packaged knowledge layer changes through reviewed compilation/distribution; live Wiki retrieval records the exact version or snapshot used. Models and harnesses may execute the same semantic strategy better as their capabilities improve. Verify that improvement against observable outputs and acceptance standards; it is not an automatic quality guarantee or permission for runtime self-modification.

Use node definitions, strategy hashes and actual dependency links to mark affected outputs stale. Apply the same impact rules to explicit manual invalidation. Keep valid independent branches and preserve old executions.
